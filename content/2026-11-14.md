# Unity

## Profile

久しくやっていないので、最近はどうやるのかを学びつつ理解を深める。

![Stats](/public/images/blog/2026-11-14/stats.png 'Stats window image')

`Stats` を選択すると FPS や SetPass call の数など、その画面をレンダリングする上での状態を確認することができる (Profiler ばかり触っていたので、初歩的な機能にも関わらず知らなかった) 。

次は `Profiler` について。例えば CPU module を見てみる。

![Timeline](/public/images/blog/2026-11-14/timeline.png 'Timeline image')

上部の録画ボタンを押した状態で、Unity Editor の Play モードに移行し、適当なタイミングでストップする。するとその Play モードにおけるシステムの負荷状況が記録される。

今 `Timeline` モードで負荷を表示している。CPU モジュールを見ると、Scripts 起因の負荷が高いことがわかる。Timeline の Main Thread を見ると、Scripts 起因の負荷の主要因が確認できる。Main Thread の青のカラーバーをクリックすると

```txt
OptimUnit.Update() [Invoke]
0.002ms

Current frame accumulated time:
4.18ms for 2000 instances on thread 'Main Thread'
MonoBehaviour: OptimUnit(Clone)
```

と表示される。つまり OptimUnit.Update の内部に負荷の原因があると分かる。

次は更に行単位で原因を追求していく。

```csharp
void Update()
{
    Profiler.BeginSample("Handling Time");

    HandleTime();

    Profiler.EndSample();
}
```

このように Profiler クラスの `BeginSample`, `EndSample` を利用するとその区間の負荷を記録できる。この状態で再度記録を行い、次は Timeline ではなく `Hierarchy` モードで内訳を見る。

![Hierarchy](/public/images/blog/2026-11-14/hierarchy.png 'Hierarchy image')

今回の `Handling Time` にかかっている負荷を見ることができる。
